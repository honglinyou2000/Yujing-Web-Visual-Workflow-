# 官网高审美视觉工作流

分阶段使用开源设计 Skill 的方法与规则，做出专业、科技感、强交互的公司官网/落地页。不要同时把全部规则塞进同一轮上下文。

## 何时运行
- 新开官网或落地页的视觉/前端
- 用户要求「审美高」「科技感」「强交互/多动效」「不要 AI 模板味」
- 已有大纲，进入视觉稿、组件或页面实现

## 固定输入（开跑前对齐）
- 受众与一句话定位（slogan 已定则写入 brief）
- 信息架构：先诊断再方案类站点，避免细产品目录页抢戏
- 品牌：logo/色板若缺，用临时 tokens 并标「待品牌定稿」
- 动效默认档：强 / 标准 / 减弱（尊重 `prefers-reduced-motion`）
- 参考正文：仓库内 `design-skills/` 下的 frontend-design、ui-ux-pro-max、taste-skill、impeccable（含 animate）

## 五步（严格按序；每步只加载对应规则）

### 1. 定方向（frontend-design）
- 写 Direction Card：气质、字体、主色/强调色、构图、一个签名动作
- 禁止默认「紫渐变 + Inter + 三卡片」
- 气质锚点可参考：冷静工程感 / 精密仪器 / 控制台被点亮
- 产出：`docs/DESIGN-direction.md`，确认后再写大段 UI

### 2. 固化系统（UI UX Pro Max）
- tokens：色、字号、间距、圆角、阴影、组件状态
- 动效：有意义的滚动叙事与微交互；可参考 GSAP 预设思路
- 产出：`docs/DESIGN.md` 或 CSS 变量

### 3. 实现（tokens → 区块 → 状态）
- 强交互按 brief：滚动叙事、磁性按钮、卡片扫光、数字缓动、视差、短转场、方法页轴线进度
- 边界：无强制长开场、CTA 始终可点、尊重减弱动效
- 产品命名仅用已批准名；无授权案例用诚实空态

### 4. 去味（Taste 规则，动效强度不照搬）
- 反模板、一屏一主区块、边距齐
- brief 要求强交互时以 brief 为准，只借去 AI 味

### 5. 终审（Impeccable，含 animate）
- 桌面+移动批量问题列表 → 改 → 再看
- 查层级、间距、对比、焦点、触控、响应式、动效表意

## 与文案/业务的边界
- 不管虚构公司事实；背书/案例只用已批准材料
- 「先诊断再出方案」优先于细方案说明书式页面

## 完成定义
- Direction Card + tokens
- 至少一页可交互预览
- 强/减弱动效可用
- 终审问题已清或标明遗留
